# ADR-0015 — فرانت‌اند: URL به‌عنوان منبع حقیقتِ نما، basemap قابل‌کاوش، i18n درون‌سازمانی

**Status:** Accepted · **Date:** 2026-09-12

## Context
سه تصمیم در فرانت‌اند باید زود گرفته می‌شد چون همه‌ی اجزا به آن‌ها تکیه می‌کنند:

1. **حالت نما کجا زندگی می‌کند؟** مرکز/بزرگ‌نمایی/سال/پنجرهٔ زمانی/تقویم/لایه‌ها/موجودیت انتخابی.
   اگر فقط در state محلی React باشد، هیچ نمایی قابل اشتراک‌گذاری یا بوک‌مارک نیست — و «لینک
   دوطرفهٔ مقاله ↔ موجودیت ↔ نقشه» که خواستهٔ اصلی محصول است شکست می‌خورد.
2. **Basemap از کجا می‌آید؟** ما کلید هیچ سرویس نقشهٔ تجاری را نداریم و اطلس باید در محیط‌های
   بسته (sandbox، شبکهٔ داخلی دانشگاه) هم کار کند.
3. **i18n با چه کتابخانه‌ای؟** فارسی RTL زبان اول است و انگلیسی دوم؛ تاریخ‌ها باید هم با رقم فارسی
   و هم با مبدأ قمری/شمسی/میلادی نمایش داده شوند.

## Decision

### ۱) URL تنها منبع حقیقتِ نما است
`lib/atlasState.ts` یک codec دوطرفه است: `MapState ⇄ query string`.

| param | معنا |
|-------|------|
| `c` | مرکز `lat,lon` |
| `z` | بزرگ‌نمایی (با `roundZoom` به نیم‌واحد گرد می‌شود تا cache مؤثر بماند) |
| `t` | سال فعال (مقدار منفی = پیش از میلاد، astronomical) |
| `from`,`to` | پنجرهٔ زمانی (temporal zoom) |
| `cal` | تقویم نمایش (`gregorian`\|`islamic_lunar`\|`islamic_solar`) |
| `mode` | `at`\|`during`\|`overlaps` |
| `l` | لایه‌های فعال |
| `entity` | موجودیت باز (`type:slug`) |
| `q` | عبارت جست‌وجو |
| `play` | پخش تایم‌لاین |

نتیجه: هر نمای اطلس یک URL است؛ `router.replace` با `scroll:false` تاریخچه را پر نمی‌کند، و
کلید back مرورگر همان «بازگشت به نمای قبلی اطلس» است. هیچ state نمای دیگری وجود ندارد —
کامپوننت‌ها از state مشتق‌شده می‌خوانند، نه از یک store موازی.

### ۲) Basemap: کاوش، سپس fallback محلی
`MapCanvas` پیش از ساخت نقشه یک `fetch` با timeout چهار ثانیه روی
`https://tiles.openfreemap.io/styles/liberty` می‌زند:

* پاسخ سالم → همان style (بدون کلید، بدون حساب کاربری).
* هر خطا/timeout → `fallbackStyle()` محلی (پس‌زمینهٔ خاکی + لایه‌های دادهٔ خودمان + graticule).

چرا کاوش به‌جای `map.on('error')`: یک خطای گذرای کاشی نباید basemap سالم را نابود کند.
خطای glyph هم بی‌صدا لایهٔ برچسب را خاموش می‌کند — خواننده نباید کنسول را ببیند تا بفهمد
نقشه کار می‌کند. لایه‌های داده پس از هر `styledata` دوباره ساخته و آخرین payload بازپخش می‌شود
(`replayAtlasData`)، بنابراین تعویض style داده را از بین نمی‌برد.

### ۳) i18n درون‌سازمانی، بدون وابستگی جدید
`lib/i18n.ts` دو دیکشنریٔ fa/en و توابع قالب‌بندی دارد (رقم فارسی، سال با مبدأ، برچسب
certainty/precision/mode/status). دلایل:

* پیام‌های UI کم و پایدارند؛ دادهٔ چندزبانهٔ واقعی (نام‌ها، خلاصه‌ها) از **API** می‌آید نه از
  فایل‌های ترجمه — پس کتابخانهٔ i18n فقط پوسته را ترجمه می‌کند.
* `next-intl`/`i18next` مسیرهای route و cache خود را تحمیل می‌کنند؛ ما segment `[locale]` و
  middleware negotiation داریم و همین کافی است (AGENTS.md قاعدهٔ ۱۴: وابستگی غیرضروری ممنوع).

### ۴) MapLibre فقط presentation است
هیچ منطق تاریخی در map/style نیست: `mapStyle.ts` فقط با کلیدهایی که API می‌فرستد کار می‌کند
(`layer`, `certainty`, `rank`, `geometry_kind`). زبان بصری عدم‌قطعیت (خط‌چین برای
`reconstructed`، توخالی برای `uncertain_locus`) از `certainty` مشتق می‌شود، نه از حدس фрانت‌اند.

## Consequences
* مثبت: نمای قابل اشتراک‌گذاری/بوک‌مارک؛ دیباگ با URL؛ کارکرد آفلاین با fallback؛ بدون وابستگی
  i18n؛ جدایی کامل presentation از داده.
* منفی: codec دستی باید با هر فیلتر جدید API به‌روز شود (یک فایل، با type صریح)؛ کاوش basemap
  یک round-trip اضافه در load اولیه می‌گذارد (موازی با fetch داده، پس محسوس نیست).
* بعدی: وقتی PMTiles آمد (ADR-0011) فقط `mapStyle.ts` و منبع داده عوض می‌شوند، نه state و نه
  کامپوننت‌ها.
